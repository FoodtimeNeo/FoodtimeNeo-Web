# 本地开发与三端联调

在Web根目录使用Node.js24与npm，先运行 `npm ci`。无需在代码或环境文件保存真实账号、密码、Cookie或CSRF令牌。

## 选择后端

| 用途                         | 浏览器地址              | `VITE_API_PROXY_TARGET`                                 |
| ---------------------------- | ----------------------- | ------------------------------------------------------- |
| 普通本地开发                 | `http://localhost:5173` | 默认 `http://127.0.0.1:8080`                            |
| 此前专用隔离库               | `http://localhost:3000` | `http://127.0.0.1:18080`，须自行启动对应隔离服务        |
| 用指定服务器数据预览本地页面 | `http://localhost:5173` | `https://kfcvivo50.ddns.net` 或 `https://154.9.252.201` |

例如在PowerShell中使用指定服务器：

```powershell
$env:VITE_API_PROXY_TARGET='https://kfcvivo50.ddns.net'
npm.cmd run dev -- --port 5173
```

连接本机8080时，在同一终端将该变量改为 `http://127.0.0.1:8080`，或移除本次终端设置并确认本地环境文件没有旧值。修改代理后重启Vite；不要把后端完整URL填进浏览器API前缀。

| 配置                        | 含义                                                                                     |
| --------------------------- | ---------------------------------------------------------------------------------------- |
| `VITE_API_BASE_URL=/api/v1` | 浏览器始终使用同站API前缀，HTTP层限制外站和非约定路径                                    |
| `VITE_API_PROXY_TARGET`     | 仅改变开发代理目标；接受无凭据、无路径/参数/片段的本机来源，或指定IP的默认HTTP/HTTPS来源 |

代理检查位于 `scripts/dev/proxy-target.js`。其他外站和该IP的非默认端口被拒绝。开发服务绑定localhost且使用严格端口；端口占用时会失败，不会静默换端口。后端默认CORS允许localhost:5173和localhost:3000，使用127.0.0.1页面来源或其他端口前要核对实际CORS配置。

## 认证与数据边界

浏览器通过同站代理管理HttpOnly Cookie；页面刷新从Backend恢复身份。登录后CSRF重新获取，写入不自动重放。后端默认dev环境启用测试开关时，注册可手工填写 `000000` 而不发送邮件；Web不生成验证码或伪造注册成功。prod后端拒绝启用测试通道，真实投递状态以实际SMTP配置为准。

线上数据预览只用于已授权的登录和浏览。自动评论、上传、审核、删除和账号调整验收应使用专用隔离库；单元测试替身不注入正常运行。Android可直接连接指定服务器，本地设备测试则通过ADB映射访问专用Backend，详见同级Android仓库的 `docs/build-and-test.md`。

## 检查与交付

```sh
npm run check
```

`check` 已包含Lint、格式、单元测试和生产构建，通常不需要随后重复构建。单独 `npm run build` 用于准备 `dist`，可用 `npm run preview` 检查构建输出。生产入口仍需正确配置HTTPS、SPA路由回退及同站 `/api/v1`（包括媒体）反向代理；Vite开发进程和CI产物不是服务器部署。

## 常见问题

- 代理连接失败：核对目标服务、端口与readiness，确认当前终端/本地环境文件中的目标；不要仅凭旧进程记录判断服务仍在运行。
- 登录后仍是访客：核对是否混用localhost与127.0.0.1、Cookie作用域、HTTPS/Secure配置，以及真实服务端会话状态。
- 图片返回404：除媒体文件缺失外，也可能是未登录、私有资源或父级已停用。Backend的V5/V6图片需要另外铺放文件及元数据，不能由Web补造图片引用。
- 提交失败：先查看“我的提交”确认结果，保留原稿，避免重发尚未确认的写请求。

菜单与详情评分均来自后端实时汇总，无评分显示“暂无评分”；需要配套最新Backend列表接口。已支持点评点赞、回复及回复点赞；菜品点赞不在本轮范围；具体字段与权限见 [后端接入](backend-integration.md)。
