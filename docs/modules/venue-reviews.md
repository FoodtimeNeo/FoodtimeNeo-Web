# 餐厅与档口点评

在现有食堂/档口详情标题下增加独立均分、人数、「查看评论」「写点评」，保留原目录、搜索及菜品价格展示。列表卡片从目录接口取得评分，首页和食堂列表返回时刷新，避免刚审核的评分被旧缓存遮挡。

## 页面与行为

- `/venue/:type/:targetId/reviews`：type 为 hall / stall，最新公开评价优先，全部/5分/4分/1–3分筛选，游标加载更多。本人待审/驳回项位于评论处，虚线卡片显示「审核中/未通过 · 仅自己可见」。公开统计及筛选不含这些项。
- `/venue/:type/:targetId/reviews/new`：现有星级键盘控件 + 必填 1–500 字正文，Unicode 码点计数。修改时带入原文；驳回重提带入最近驳回文本。待审时阻止再次新建。
- 楼层内展开回复，公开回复和本人待审回复分别分页。实际回复对象 ID 随提交发送；收起回复、刷新审核不清空编辑器。一级点评点赞和回复点赞沿用现有控件与版本计数。
- `/profile/venue-reviews`：从「我的」进入，可筛餐厅/档口、一级点评/回复，查看状态和原因，修改或确认删除。
- 管理审核页新增四个类型；完整内容对照原公开评价与本次提交，审核后刷新列表；下架原因必填并生成日志。公开正文不使用 HTML 渲染，邮箱仅在管理员页面显示。

## 状态与故障

公开接口从不混入本人待审。本人状态从会话对应 `/me` 读取，刷新页面可以恢复。提交成功先保留接收结果，再从服务器核对；单路读取失败分别提示，保留已成功读取的内容。修改待审时旧公开版本继续显示，通过后按稳定楼层 ID 更新，不重复计数。

仅本人存在待审内容时短时更新状态，每 2 秒、最多 30 秒，页面隐藏或组件销毁停止；恢复前台或手动刷新可重新核对。没有全站常驻轮询。回复刷新不重建编辑器；失败保留输入及同一次操作 ID，输入实质变化才换 ID，避免超时后重试重复创建。

草稿和接收结果只在本次浏览器内存中按账号隔离，退出清除；无 localStorage 私密正文。离页取消读取，账号变化后旧结果不回填。所有写入沿用 CSRF、Cookie 和服务端限流；访客禁止评价/回复/点赞。错误不会回退到样例数据。

## 验证与上线

组件测试覆盖本人隔离、XSS 文本显示、公开请求失败、修改过渡、驳回回填、幂等重试、账号切换和嵌入回复草稿。`npm run check` 执行静态检查、格式、全量单元测试和构建。本地真实后端 + Chrome 另验收 21 项，包含管理员发布者信息/原文对照、AI 通过/驳回、点赞、楼中楼及 390px 显示。

先部署含 V37 的后端，随后部署本 Web，无新增前端配置。生产继续使用同站 `/api/v1` 代理。
