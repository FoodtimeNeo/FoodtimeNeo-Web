# 首页每日推荐

首页“今日推荐”读取已登录会话的 `GET /api/v1/recommendations/daily`，由公共 HTTP 层解包 `.data`。已删除原来的五道示例菜品，不缓存示例或以食堂列表代替推荐。

- 接口不携带用户 ID、日期、排序或数量参数；同一业务日的推荐由后端决定。
- 使用 `dishId`、`diningHallId`、`stallId` 构造 `dishDetail` 路由；顺序保持后端批次顺序，轮播组件仍保留拖拽和自动滚动行为。
- `averageRating` 才是实际星级；为空显示“无评分”。`recommendationScore` 是算法分，不作为评分展示。图片为空使用现有图片占位，不虚构价格。
- 卡片显示真实食堂、档口和 `reason`。校验日期、总数、唯一菜品、父级 UUID、数值及枚举，异常响应进入错误状态。
- 加载、空列表和错误分别展示独立状态，错误可重试。没有推荐时仍可浏览下方食堂。切换账号或角色会取消请求并清空卡片，卸载和迟到响应受请求代次保护。
- 业务日期不按浏览器时区换算；当前首页不显示日期，仅展示服务端当日批次。

推荐接口依赖后端 V38 迁移；后端必须同时包含看板的 `totalUsers`、`trend[].totalUsers` 和 30 日接口支持。直接切换至旧推荐分支会丢失这些看板字段。

本地验收：`npm run check`（91 个文件、411 项测试，含接口校验、真实路由、失败重试、空列表和账号切换）。真实 PostgreSQL/Redis/HTTP 联调覆盖十道推荐、详情跳转、访客、375px 屏幕、加载、空列表、503 后重试，以及管理看板兼容；记录见项目根目录 `docs/每日推荐接通验收-20261104.md`。
