# 安全自动更新与旧页面恢复

本功能自 v2.1.0 提供；部署时需配套保留旧静态资源并采用下述缓存规则。发布制品不直接修改线上 Nginx。

## 客户端行为

- 启动、回前台、恢复联网和资源加载失败时检查构建号；前台也会定期检查。常规版本请求最多每分钟一次，错误触发的强制检查最多每30秒一次，并发检查合并。
- 阅读页面且停止操作至少1.5秒时可以自动切换；有改动的文字、密码、文件选择、星级等控件、中文输入法组合、弹窗、上传/写请求或本机草稿写事务时暂停。没有统一持久化能力的表单保持原页，直到恢复原值、完成并清空表单、关闭编辑器或正常离开该页；不擅自保存密码或私信。
- 原发帖草稿继续按账号/服务来源存入 IndexedDB；等待保存事务结束再更新。保留 Cookie、登录会话、IndexedDB、localStorage 和其它站内功能的数据。
- 只清理 `foodtime-static-*`、`foodtime-shell-*` 旧应用壳缓存，不注销 Service Worker，不清媒体缓存或同站其它应用缓存，不发送 Clear-Site-Data。
- 更新前核对 version.json、当前路由的 HTML、实际入口 JS 和 SHA-256；旧格式元数据需核对实际入口中的构建号。半部署、HTML旧缓存、入口404/回退HTML、校验不符时保留当前页，30秒后再检查资源。请求有超时，不会永久占住检查队列。
- 更新保留路径、查询参数和锚点，尝试恢复滚动位置；同一目标构建每个标签页最多自动切换一次，存储不可用时仍使用 URL 防循环。
- 提示为非阻塞的手账样式状态条，不要求点击确认，也不会通过“立即刷新”绕过内容保护。

## 接口错误与兼容

API 请求带公开构建号 X-Foodtime-Web-Build，后端只用于日志关联，不用于授权。没有此头的 Android/旧网页照常工作，现有 API v1、会话、CSRF、角色和业务响应结构不变。本次不把旧请求统一改成500，也不改写既有数据库迁移。

只读 GET 遇到网络/超时、502/503/504，在线且会话没变化时最多重试一次；500、401/403/429和写操作不自动重放，取消/切号后不重试。真实错误仍暴露到原页面，5xx提示附服务器请求编号。客户端错误对象仅保留安全的编号/构建号，不保留 Axios 请求体、密码、验证码、Cookie 或令牌，不增加遥测上传端点。

后端日志按 requestId/clientBuild 关联，5xx汇总只含方法、路径（不含查询）、状态和编号。构建号由客户端自报，只能用于排查，不能据此绕过权限或强制老客户端升级。后续变更接口应保持旧字段兼容或单独设计版本契约，不能靠刷新掩盖服务端异常。

## 部署

1. 备份原站点及配置。解压新构建到独立目录 incoming，不覆盖运行目录。
2. 使用 Node 24 的工具准备全新目录：
   `node scripts/deploy/prepare-web-release.js /srv/incoming-dist /srv/releases/new-build /srv/current`
   父目录须已存在，输出目录必须不存在且独立。工具校验元数据/入口，保留 current/assets 中不冲突的历史哈希资源；发现同名异字节或私密配置立即失败。失败只留下未启用的准备目录，不会更改当前站点。
3. current 可以是运行目录或其符号链接。验证新目录的路由、版本、API与下载后，按原运维方式原子切换站点目录/链接；勿先删除原 assets 再拷贝。保留至少7天的旧哈希资源，覆盖长期打开标签页，之后由运维结合空间与使用情况清理；工具不会自动删历史资源。
4. 合并 deploy/nginx-spa-cache.conf.example 的缓存规则：HTML/SPA每次校验、version.json不存储、sw.js每次校验，哈希assets长期不可变缓存且缺失必须404。/api反代保持原样。示例 include 路径应换成实际安全头文件，文件内容沿用当前 HSTS、CSP、nosniff 等全部安全头；不能只复制 Cache-Control 导致继承的安全头消失。部署前先 nginx -t。
5. CDN/代理同步使用以上策略，发布时刷新入口HTML和version.json；不清用户数据。后端如使用显式 CORS header 白名单，加入 X-Foodtime-Web-Build，保持现有 Origin 白名单不变。

新机制必须随新版部署后才生效。已经运行的更旧 JS 无法被远程改写，首次过渡仍受旧版刷新逻辑限制；没有更新能力的古老标签页通常需等下一次正常导航或浏览器更新。不能承诺所有旧页面瞬间无感恢复。保留资源和后端兼容可降低过渡期出错。

## 验证

单测覆盖内容保护、并发写入/CSRF失败释放、重试上限、500保留与编号、离线/半部署/校验失败/防循环、旧资源保留和活跃目录保护；生产构建核对真实入口哈希。浏览器用两个真实构建及受控后端响应验证切换和输入保留，不能冒充线上根因或实际邮件联调。准确结果见本次 PR 和工作区 test/safe-web-update-2026-11-23/。
