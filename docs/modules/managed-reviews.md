# 正式菜品点评管理

2026-11-03，以 `develop` 的 `10829cd` 为基线，在 `feature/review-management-dialog` 实现已审阅的“单列摘要·详情弹窗”方案。

## 页面范围

`/admin/reviews` 继续通过 `GET /api/v1/admin/reviews?q=&page=&size=20` 读取已公开的菜品点评，支持按用户 ID、邮箱、昵称查询。查询、清除筛选回到第一页；翻页保留用户条件。餐厅、档口、社区评论与回复仍由已有内容审核入口管理，本轮不扩展管理接口或类型筛选。

## 展示与操作

- 保留当前纸张风格、横向管理导航和单列卡片。卡片头显示菜品、所属食堂／档口及五分制评分；宽屏发布者名称／邮箱／ID／发布时间两列排列，窄屏改为单列。
- 列表正文最多两行，AI 建议使用摘要；“查看完整内容”展示原文、点评标识、发布时间、更新时间（如有）及完整 AI 分诊信息。内容全部使用文本插值，不执行正文中的 HTML。
- 完整详情来自当前列表记录，不增加逐条详情请求。分页仍每页 20 条，没有退回示例数据。
- 列表和详情中的“删除违规评论”进入同一弹窗内的原因表单，继续调用 `DELETE /api/v1/admin/reviews/{id}`。原因必填，校验失败聚焦输入框；请求期间禁止重复提交、关闭与 Escape 退出。失败保留原文和原因，成功关闭弹窗并更新列表。删除末页最后一项后回到有效页码。
- 删除成功与列表刷新失败分别提示，避免误以为删除没有执行。长正文仅在弹窗正文区滚动，底部操作保持可见；手机按钮至少 44px 高。

## 审核日志分类检查

对照 Web 日志页和最新 Backend `origin/dev`（`9dfa18a`）：

- **内容类型已有**：菜品点评、新菜品、档口投稿、图片、菜品点评回复、餐厅／档口点评及其回复、社区食记、社区评论／回复，合计 11 种 `type`。
- **处理结果已有**：`approve`、`reject`、`remove`；页面显示通过、驳回、下架。
- **审核来源已有**：`actor` 区分人工与 AI，AI 可显示模型名。
- **分类筛选尚未提供**：页面没有分类筛选控件，`GET /admin/moderation/logs` 只接收 `page`、`size`，服务端按时间倒序返回混合日志，不能只筛选当前页后当作全量分类结果。
- **正式菜品点评删除的记录边界**：现有后端只将该操作及原因写入服务器操作日志，不新增页面使用的 `content_moderation_logs` 项。本轮保持既有后端语义，未把页面分类标识误写成已具备分类筛选或完整删除记录。

## 验证

执行 `npm run check`，覆盖静态检查、格式、全量 Vitest 与生产构建。回归用例覆盖查询分页、完整字段和文本转义、删除原因必填、失败保留输入、提交防重及禁止关闭、删除成功但刷新失败、末页删除回退。

使用隔离本地后端与真实浏览器验证长正文、HTML 字样、查询空结果恢复、手机布局及真实删除；仅生成和删除本轮专用测试点评，不操作云端数据。
