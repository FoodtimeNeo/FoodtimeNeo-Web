# Web 真实后端接入

本轮只修改 Web。接口以现有 Backend 的 `docs/api` 和 `docs/database-design.md` 为依据，不补造后端字段或接口。按用户确认隐藏邀请码、吐槽、推荐/避雷、今日推荐及排行榜等未支持入口；不新增点赞、收藏或分类。正式邮箱投递仍暂不验证。

## 认证与请求

- 本地开发使用 `/api/v1` 同站请求，Vite 将 `/api` 代理至 `http://127.0.0.1:8080`。生产需将同站 `/api/v1` 代理至 Backend，并使用 HTTPS；不能把开发服务器当作生产部署。
- Cookie 由浏览器和服务端管理，前端不读取 HttpOnly Cookie、不保存 Token/角色/密码。重新打开页面通过 `/auth/me` 获取当前身份，管理路由重新校验服务端角色。
- 写请求先获取 `/auth/csrf`，令牌只在内存中保留。登录更换会话后重新获取；CSRF 失效不自动重放写请求。
- 登录使用 `account/password`；注册仅使用 `email/password/verificationCode`。客户端角色、昵称、邀请码不参与注册授权。
- 响应必须是 `code: "OK"` 的统一结构。401 清除页面身份，403/429/503 保留服务端错误；错误对象不包含原始请求和凭据。
- 不启用旧 Mock 后端或本地身份回退。旧版凭据会清理；切换账号后的迟到响应不能覆盖当前页面身份。

## 功能分支与验收

以当前 `develop` 为集成分支，每个功能单独开发，提交使用 `feat: 中文描述` 等格式。已实现认证请求基础；接下来分别接入目录与详情、投稿和个人记录、内容审核与目录管理、用户管理，并通过真实浏览器验证。

每个功能提交前运行 `npm run check`。单元替身只用于验证前端行为，不能作为已与 Backend 联调的证据；真实接口和页面验收结果在完成对应功能后记录。
