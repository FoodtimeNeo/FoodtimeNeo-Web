# 登录公告展示

成功登录或刷新页面恢复会话后请求 GET /users/me/notices/current 一次；用户 ID 不变的资料刷新、路由切换和前后台切换不触发重复请求。退出、切号、组件卸载时取消旧请求并丢弃晚到的结果。

data=null 表示未配置当前公告或该用户已免弹。非空内容使用 content 渲染 Markdown；没有独立标题字段。弹窗使用固定“系统公告”标签，Markdown 自带标题仍在正文中显示。长文可滚动，确认按钮和复选框保持可见。

打开不写已读。点击确认才 POST /users/me/notices/{id}/confirm，发送 dontShowAgain 布尔值。复选框默认关闭；未勾选也会记录已读，但下一次登录仍可弹。勾选后免弹选择在服务端保存，跨设备生效。失败保留弹窗与选择，允许重试；旧账号的确认回调不能关闭新账号的弹窗。

使用 markdown-it（关闭原始 HTML）和 DOMPurify 清洗渲染结果；危险链接、脚本和本地文件图片不执行。历史公告详情使用同一渲染组件和确认行为。已取消公告轮询及 localStorage 公告水位，未读计数只在登录、进入信箱及读操作后按需查询。

公告管理入口和后端发布权限均限制 superadmin。创建/编辑 UI 的 content 化、当前公告配置 UI 后续完成；本轮不新增这些管理功能。

需要 Backend V27 及配套接口。config 只有 id、notice_id 两列；初始化 notice_id=NULL 时不弹出，不自动选择最新公告。首次启用需在管理流程完成前明确配置当前公告 ID。
