# 菜品点评互动与实时评分

2026-10-20 起按功能分支逐项实现实时评分、点评点赞、回复、回复点赞，集成分支为 develop。

## 界面与交互约定

采用 Extension 模式，延续牛皮纸、深棕正文、红色评分章、2px边框和硬阴影；使用现有 tokens.scss 中的字体与8px间距体系。设计校准为视觉变化3、动效2、密度6、素材依赖2、品牌保真10：只补充评论内操作，保留既有路由、主导航和素材，增加个人回复子页面。正文16px、辅助14px；按钮至少44px，移动端换行布局。

写请求期间禁用同一目标的重复操作并显示进度，失败保留原状态和输入；错误就近显示，按钮有文字及键盘焦点。回复按展开动作分页加载，进入审核的内容明确显示待审核，不冒充已公开。

## 实时评分

`GET /dishes/{id}/rating` 与菜品列表返回服务端事务内维护的 averageScore/reviewCount。无评分保持NULL，界面显示“暂无评分”；不在浏览器重新平均。后端已取消每日评分任务；每次进入详情重新读取汇总，不轮询计数。评分只计算未删除的正式一级点评。

主点评重新审核通过保留原ID、首次时间和互动；删除后重发使用新ID。两类点赞和回复都不影响菜品评分。后续互动接口与状态说明随各功能提交维护。

## 一级点评点赞

评论列表读取 likeCount/likedByMe/counterVersion。PUT /reviews/{id}/like 点赞，DELETE同路径取消；不发送身份和计数。按钮用服务端响应更新，处理期间禁用并显示反馈，失败保留旧状态并显示错误。较旧计数版本不覆盖新值，不为一次点赞重载整页。

## 点评回复

点评内展开时才请求一页20条回复，后续使用nextCursor；total使用后端统计。支持回复一级点评或同楼回复，replyToId结构化提交，删除对象显示占位。POST返回审核提交回执，待审内容不插入公开列表。输入失败保留，clientRequestId在同一内容/对象重试时复用，服务器去重；变更内容创建新操作。自己的回复先确认再删除。

个人页新增“我的回复”(/profile/review-replies)，分页显示pending/approved/rejected、审核原因及原点评已删除状态。管理端内容审核识别dish-review-reply，显示AI结论并支持人工决策；已通过回复可填写原因后删除。网络状态、空列表、删除确认和错误沿用现有组件。

## 回复点赞（2026-10-20）

PUT/DELETE /review-replies/{id}/like 与一级点评点赞共用按钮状态处理，返回likedByMe/likeCount/counterVersion；回复列表直接附带三字段，无额外逐条读取。处理期间禁用操作，失败保留原状态，不重载楼层或菜品页，较旧响应不能覆盖新版本。只有审核通过且未删除的可见回复可新增点赞；隐藏历史允许本人取消。两类点赞均不影响菜品评分。
